# Modular monolith

The project is split into one executable Micronaut module and several library modules.

## Modules

`apps/service` is the application runtime. It contains `Application`, configuration, logging, and dependencies on all internal modules.

`modules/cqrs` contains shared CQRS contracts, a synchronous command bus, and a query bus. The API creates commands or queries, while implementation modules register handlers.

`modules/catalog` will hold the source project model, paths to `.md` files, and page metadata.

`modules/downloader` will contain ports and adapters for downloading Markdown content from the source.

`modules/storage` will contain ports and adapters for storing downloaded pages.

`modules/scheduler` will manage scheduled or manual downloads.

`modules/api` will expose HTTP endpoints for status, configuration, and manual execution.

## Dependency Rules

`apps/service` may depend on every module.

`modules/api` may call `modules/scheduler` and read models from `modules/catalog`.

`modules/api` may dispatch commands and queries through `modules/cqrs`, but it must not contain downloading, storage, or scheduling implementations.

`modules/scheduler` may compose `modules/downloader`, `modules/storage`, and `modules/catalog`.

`modules/downloader` and `modules/storage` must not depend on `modules/api`.

`modules/downloader` may implement query or command handlers from `modules/cqrs`.
