# cqrs

Shared application CQRS contracts.

The command side is intended for operations that change state and do not return application data. The query side is intended for read operations and returns results.

## CommandBus

`DefaultCommandBus` is not only a direct dispatcher. During `dispatch`, a command passes through these steps:

1. validation through `CommandValidator`
2. authorization through `CommandAuthorizer`
3. idempotency key from `CommandDispatchOptions`, or from `IdempotentCommand`
4. storage in `CommandStore`
5. handler execution inside `CommandTransactionBoundary`
6. audit/logging through `CommandAuditListener`
7. retry decision through `RetryPolicy`
8. error mapping through `CommandErrorMapper`

The default Micronaut bean `FileCommandStore` stores the command journal in the
`md-page-harvester.command-bus.store-file` file. The local default path is
`build/command-bus/commands.bin`; Docker and Portainer configuration set it to
`/data/command-bus/commands.bin`, which is backed by a persistent volume.

After an application failure, call `CommandBus.recoverPendingCommands()`. It processes commands in
`PENDING`, `PROCESSING`, and retry-ready `FAILED` states.

When a command has no explicit idempotency key, the bus assigns a unique intent id and will not merge two operations that look the same.

Packages are split by responsibility:

- `command` - public command contracts
- `command.bus` - bus implementation and handler registration errors
- `command.validation` - validation hooks
- `command.authorization` - authorization hooks
- `command.store` - persistent journal and stored commands
- `command.retry` - retry policy and retry decision
- `command.transaction` - transaction boundary
- `command.audit` - audit/logging listener
- `command.error` - error mapping and dispatch exceptions
- `command.idempotency` - internal idempotency key resolver
